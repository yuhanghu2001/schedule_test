# 上位机可视化调度系统设计（前后端分离）

开发启动：首次在仓库根目录执行 `npm install`，随后用 `npm start`（或 `npm run dev`）自动准备 MySQL 8.4.2（`127.0.0.1:3306`）、启动 FastAPI（`8000`）和 Vite（`8888`）。Python 入口通过 `conda run --no-capture-output -n gatppo python -m scripts.dev` 使用已有环境；MySQL 使用 `.local/mysql-env` 独立 Conda 环境，首次安装需联网，无需 sudo。浏览器访问 `http://localhost:8888`，REST/WebSocket 由 Vite 代理。`Ctrl+C` 停止应用后关闭数据库，保留数据。npm workspace 统一维护根目录 `package-lock.json`，详见根目录 [README](../README.md#前端后端和-mysql-一键启动)。

本文档定义 `schedule_test` 上位机可视化调度系统的功能规划、前后端架构、MySQL 数据表、`localStorage` 缓存规范与 REST/WebSocket 接口契约。所有实现均须遵守 `AGENTS.md` 硬规则：**最简直接、不写防御式校验代码、后端直接复用 `src/` 核心算法与仿真引擎，严禁复制仿真动力学逻辑**。

## 1. 技术栈与目录结构

- **前端**：Vue 3 + Vite + Element Plus + Vue Router + Pinia + Axios + ECharts（浏览器缓存使用 `localStorage`）。
- **后端**：FastAPI + Uvicorn + SQLAlchemy 2.x + PyMySQL + WebSocket（直接运行在 `gatppo` conda 环境中以复用 `src/`）。
- **数据库**：MySQL 8.x（通过 `backend/.env` 配置连接信息，提供 `backend/schema.sql` 一键建表，不内置 SQLite 回退）。
- **训练产物**：正式训练权重、日志与曲线仍严格写入 `results/YYYYMMDD_HHMMSS/`，MySQL 保存元数据与逐回合指标索引。

## 2. 功能模块规划

### 2.1 模型训练工作台（核心主模块）
1. **仿真环境搭建**：
   - 加载 `default` / `high_congestion` / `small_smoke` 预设或从 MySQL 载入已保存配置；
   - 可视化调整 `n_terminals`、`n_edges`、`undirected_edge_links`、`episode_slots`、`arrival_rate`、`burst_prob`、`topology_period_slots`、`link_flap_prob`、`congestion_ar_coef`、`link_spike_prob`、`link_rate_fluctuation`、`max_hops`、`k_routes_per_destination` 等参数；
   - 表格直接编辑每个边缘节点的异构算力（CPU/NPU/FPGA GFLOP/s）与 5 类任务服务部署开关（0/1），点击“预览拓扑”实时刷新右侧拓扑画布与节点画像；
   - 支持保存环境配置到 MySQL。
2. **算法参数设置**：
   - 选择算法模型（`gat` / `flat` / `shuffled_gat`），设置 `gat_hidden_dim`、`actor_hidden_dim`、`critic_hidden_dim`、`actor_learning_rate`、`critic_learning_rate`、`gamma`、`gae_lambda`、`ppo_clip`、`ppo_epochs`、`ppo_batch_size`、`ent_coef`、`episodes`、`seed`、`device`、`threads`；
   - 可选已有历史 Checkpoint 发起续训（`resume_path`）。
3. **调度模型训练与实时监控**：
   - 启动训练后返回 `run_id`，后台复用 `src` 核心类（`EdgeEnv` / `GATPPO` / `PPOTrainer` / `evaluate_policy`）执行训练并落盘至 `results/YYYYMMDD_HHMMSS/`；
   - 支持安全中断（停止当前训练并保存 `last` 权重与曲线）；
   - 通过 `WS /ws/training/{run_id}` 实时渲染累计奖励、任务完成率、平均时延、平均能耗、负载均衡度、平均跳数与 PPO 诊断曲线。

### 2.2 仿真环境可视化沙盘
1. **动态多跳拓扑图**：分层展示云端 $c_0$、边缘网 $\mathcal E$（链路宽度映射带宽、颜色映射拥塞热力、虚线标示瞬断链路、标签显示拥塞率与变化趋势 $\Delta\rho$）、端侧源 $\mathcal U$ 及无线接入链路；选中任务后高亮完整多跳路径。
2. **节点异构算力与资源详情**：点击任意边缘/云节点，显示 CPU/NPU/FPGA 总额与当前占用（区分跨时隙在途冻结算力与本时隙新占算力）、内存/存储/队列水位、已部署服务标签及在途任务清单。
3. **任务流明细表**：列出任务 ID、到达时隙、源端侧、接入边缘、类型、数据/计算量、截止时间 `deadline_s`、优先级、执行位置、资源芯片、多跳路径、分配算力 $f$、上行功率 $p_{up}$、估计/实际时延能耗与成败状态。
4. **交互推演控制**：支持选择策略（已训练 Checkpoint / `shortest_fastest` / `greedy_estimate`），按单任务步进、按时隙步进、连续播放/暂停、重置，并支持手动注入单条链路拥塞尖峰或断开测试重路由行为。

### 2.3 多算法对比实验室 & 实验资产管理
- **对比评估**：选择环境配置、固定评估种子列表与待比较策略（任意历史 Checkpoint + 传统基线），运行评估并生成四目标对比柱状图、雷达图与汇总表，结果持久化至 MySQL。
- **历史实验管理**：分页列出 MySQL 中的训练记录与指标摘要，支持一键扫描导入仓库已有 `results/*/` 产物、查看曲线、将配置回填至训练工作台或直接跳转到仿真沙盘加载该权重推演。

## 3. MySQL 数据表与 `localStorage` 缓存规范

### 3.1 MySQL 核心表（见 `backend/schema.sql`）
1. `env_configs`：`id`, `name`, `preset_name`, `description`, `config_json` (JSON), `created_at`, `updated_at`
2. `training_runs`：`id`, `run_name`, `model_type`, `env_config_id`, `config_json` (JSON), `episodes`, `current_episode`, `seed`, `device`, `threads`, `status` (`queued`/`running`/`completed`/`stopped`/`failed`), `best_score`, `results_dir`, `best_checkpoint`, `last_checkpoint`, `error_message`, `created_at`, `finished_at`
3. `training_metrics`：`id`, `run_id`, `episode`, `episode_reward`, `objective_score`, `task_success_rate`, `acceptance_rate`, `deadline_miss_rate`, `avg_delay_s`, `avg_energy_j`, `mean_load_variance`, `load_balance_degree`, `mean_hops_accepted`, `mean_path_length`, `loss`, `approx_kl`, `entropy`, `explained_variance`, `created_at`
4. `evaluation_records`：`id`, `name`, `method`, `run_id`, `checkpoint_path`, `env_config_id`, `seeds_json` (JSON), `summary_json` (JSON), `created_at`
5. `simulation_snapshots`：`id`, `name`, `env_config_id`, `policy_label`, `seed`, `metrics_json` (JSON), `trace_json` (LONGTEXT/JSON), `created_at`

### 3.2 前端 `localStorage` 缓存键规范（`frontend/src/utils/storage.js`）
- `st_env_draft`：训练工作台未保存的仿真环境参数草稿；
- `st_train_draft`：算法超参表单草稿；
- `st_active_run_id`：最近查看/监控的训练任务 ID；
- `st_topology_layout`：用户拖拽微调后的节点坐标缓存（按 `n_edges` 分桶）；
- `st_ui_prefs`：侧栏折叠状态、推演播放倍速、图表指标显隐开关。

## 4. 核心 REST / WebSocket 接口契约

| 方法与路径 | 用途 |
| :--- | :--- |
| `GET /api/health` | 服务健康与数据库连接状态检查 |
| `GET /api/env/presets` | 获取 `default` / `high_congestion` / `small_smoke` 完整参数预设 |
| `GET /api/env/configs` / `POST /api/env/configs` / `DELETE /api/env/configs/{id}` | MySQL 环境配置模板列表、保存与删除 |
| `POST /api/env/preview` | 根据传入 `Config` 参数实例化 `EdgeEnv`，返回拓扑节点/链路、节点异构算力/服务及首批任务快照 |
| `POST /api/sim/sessions` | 创建交互式推演会话（指定环境参数、种子与策略/权重路径），返回 `session_id` 与初始快照 |
| `POST /api/sim/sessions/{id}/step` | 单任务步进（支持可选 `action_id` 手动指定或由当前策略决策），返回本步决策与更新后全局状态 |
| `POST /api/sim/sessions/{id}/step-slot` | 推进完整一个时隙并返回最新拓扑、节点、任务与累计四目标指标 |
| `POST /api/sim/sessions/{id}/perturb` | 注入指定边缘链路的拥塞值或通断状态，返回更新后的拓扑快照 |
| `POST /api/training/runs` | 提交并异步启动训练任务（支持自定义环境参数、超参和 `resume_path`） |
| `POST /api/training/runs/{id}/stop` | 请求安全中断训练并保存当前 `last` 权重与曲线 |
| `GET /api/training/runs` / `GET /api/training/runs/{id}` | 查询训练任务列表与详情 |
| `GET /api/training/runs/{id}/metrics` | 查询训练与验证曲线数据 |
| `POST /api/training/sync-results` | 扫描 `results/*/` 历史正式训练目录并导入 MySQL（幂等去重） |
| `WS /ws/training/{run_id}` | 实时推送逐回合训练指标、评估指标和任务终态事件 |
| `POST /api/experiments/evaluate` / `GET /api/experiments/evaluations` | 固定多随机种子对比评估多策略并查询历史评估记录 |


## 5. 深蓝监控总览（2026-11-19）

首页 `/` 使用 `OverviewDashboard.vue`，以 25% / 50% / 25% 三栏组织概况、资源趋势、拓扑、任务明细、计算节点状态和调度策略。主导航仅保留“系统总览”和“节点管理”（`/nodes`）；旧 `/topology`、`/resources` 地址继续兼容，主导航移除拓扑监控、任务调度、资源管理、算法评估。`/sandbox`、`/training`、`/compare`、`/history` 分别保留原有完整推演、训练、评估与实验记录功能；历史回填转到 `/training`。

### 组件与数据来源

- `TopologyGraph.vue`：分层 SVG；云端、两排边缘与端侧均取自快照。所有链路只遍历真实 `links` 和终端的 `access_edge`，不为布局补造连接。正常链路蓝色，背景拥塞超过 0.4/0.7 时橙色/红色，失效链路虚线；选中任务的实际路径用绿色方向箭头覆盖。悬停显示链路速率与拥塞，节点可点击和拖动；新布局以 `layered-节点数` 存入原布局缓存。
- `NodeGlyph.vue`：可维护的 SVG 服务器、云与端设备图标，不使用页面截图背景。
- `NodeResourcePanel.vue`：直接复用，置于详情抽屉，显示计算资源、跨时隙占用、存储、内存、队列、服务与在途任务。
- `TaskFlowTable.vue`：新增 `compact` 展示模式，保留原候选动作与手动执行模式；修正云端路径标签为 C0。
- `ResourceTrend.vue`：ECharts 展示最近 40 次真实快照的资源利用率，以已调度任务数为横轴，不伪称真实时间的分钟趋势。
- `styles/dashboard.css`：深蓝主题、Element Plus 暗色覆盖与两种桌面分辨率适配；保留原页面的布局样式。

总览复用 `/api/health`、`/api/env/presets`、`/api/env/preview`、`/api/training/checkpoints`，以及仿真会话创建、单任务/整时隙步进、重置和删除接口。所有面板均从同一 `snapshot` 更新；选择环境会结束旧会话，创建新会话或重置时清空趋势。自动推演串行请求，暂停或离开页面后停止继续调度；重建与离开总览时删除旧会话。

### 指标口径与状态

- 完成率使用 `metrics.task_success_rate`；平均时延、能耗与负载方差分别使用 `avg_delay_s`、`avg_energy_j`、`mean_load_variance`。初始无时延/能耗样本显示“—”，不填造数值。
- 总任务量为 `total_tasks`，已调度量为 `task_index`，按期完成数从 `recent_tasks` 中 `accepted && completed` 统计。五类分布仅统计已调度任务。
- 总体利用率为全部计算节点（含云端）的资源占用之和除以对应容量之和；单节点利用率为该节点 `resource_used[i] / speed[i]`。在途跨时隙任务已包含于后端占用，不再重复相加。
- “按期完成/超时”沿用后端根据时限判定的任务结果，不表示真实时间推进到该任务完成时刻。
- 当前策略与创建会话时实际选择保持一致；Checkpoint 显示真实权重文件名。GAT-PPO 流程明确标为原理示意，不把启发式或未知类型的旧权重标成 GAT-PPO 正在运行。
- 系统状态来自健康接口；MySQL 未连接时如实提示，不影响内存推演。时间使用北京时间。

## 7. 三服务启动与本地数据库生命周期

`scripts/dev.py` 是根目录及 frontend 目录 `npm start` 的共同入口：

1. 缺少 `.local/mysql-env/bin/mysqld` 时，使用 Conda 安装固定 MySQL Server/Client 8.4.2，不修改训练环境。
2. 缺少 `backend/.env` 时生成本地连接参数与随机应用密码；首次建立数据目录，为 root 设置独立随机密码，管理员客户端文件权限为 600。
3. 启动只监听回环地址的 MySQL，等待 `mysqld --daemonize` 成功返回，建立数据库、受限于本库的应用账户及 schema.sql 中五张表；已有数据不覆盖。
4. 数据库就绪后，在当前 gatppo Python 中直接启动 Uvicorn，并启动前端 Vite。移除不再使用的 concurrently 依赖。
5. 主进程监视两个应用子进程；任一退出或用户 Ctrl+C 时，发送停止信号并等待应用结束，随后执行 mysqladmin shutdown。只有本次成功启动的数据库会被关闭。

数据、日志、MySQL 二进制环境均在被 Git 忽略的 `.local/`；应用凭据使用已忽略的 `backend/.env`。正常重启复用数据、账户与凭据，不重新生成密码。该入口面向当前 Linux/WSL 本地开发环境。

初始化和守护进程参数参考 [MySQL 初始化文档](https://dev.mysql.com/doc/refman/8.4/en/data-directory-initialization.html) 与 [服务启动选项](https://dev.mysql.com/doc/refman/8.4/en/server-options.html)。实际已连接截图：[MySQL 已连接](screenshots/mysql-connected.png)。
