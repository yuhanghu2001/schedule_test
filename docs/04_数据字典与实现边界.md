# 状态与数据字典

本文给出阶段 1B 的 v6 接口目标。已有字段沿用原型名称，新增链路状态以数学符号标识。

## 1. 环境输入

| 字段 | 对应数学含义 | 字段 / 取值 | 单位 |
| --- | --- | --- | --- |
| `N` | 端侧任务源数 | `n_terminals=24` | 个 |
| `M` | 区域边缘数 | `n_edges=12` | 个 |
| `C` | 云端数 | 1，计算节点共 M+1 个 | 个 |
| `s(i)` | 源终端的固定接入边缘 | `Task.access_edge = Task.source % M`，默认每个边缘绑定两个终端 | 下标 |
| `T_ep` | episode 时隙数 | `episode_slots`，默认/高拥塞/smoke 依次为 20/20/4 | 时隙 |
| `lambda_0` | 基础到达率 | `arrival_rate`，默认/高拥塞/smoke 依次为 18.0/24.0/5.0 | 项/时隙 |
| `N_T` | 本 episode 实际任务数 | `len(env.tasks)` | 项 |
| `Delta t` | 时隙长度 | `slot_seconds` | 秒 |
| $\mathcal A_e(t)$ | 有效有向边缘弧集合 | `EdgeEnv.adj` 的边缘子图 | 0/1 |

| $R_{mn}^{base}$ | 边缘间基准带宽 | 重构或激活时的链路基准 | Mbps |
| $R_{mn}^{ee}(t)$ | 本时隙的边缘间带宽 | `rates[m,n]`，基准带宽乘本时隙的抖动因子 | Mbps |
| $\bar\rho_{mn}$ | 有向弧的基线拥塞 | AR(1) 均值回归的参照 | 比例 |

| $\eta_i$ | 接收后固化的算力退化比例 | $U[0,0.2]$，实际算力为 $(1-\eta_i)f_{ijq}$ | 比例 |

| `T_mn^prop` | 每跳传播延时 | `prop[m,n]` | 秒 |
| `P_mn^fwd` | 中继节点转发功率 | `forward_power[m,n]` | W |
| `d_i` | 输入数据量 | `Task.data_mb` | MB |
| `o_i` | 结果数据量 | `Task.output_mb` | MB |
| `c_i` | 任务计算量 | `Task.compute_gflop` | GFLOP |
| `D_i` | 源端实际速率下的上/下行时间与最慢边缘执行时间之和乘松弛系数 | `Task.deadline_s` | 秒 |
| `t_i^{arr}` | 到达时隙 | `Task.slot` | 时隙 |
| `xi_min/xi_max` | deadline 松弛系数上下界 | `deadline_slack_min/max` | 倍 |
| `p_i` | 优先级 | `Task.priority` | 1—5 |
| `m_i` | 内存需求 | `Task.memory_gb` | GB |
| `s_i` | 存储需求 | `Task.storage_gb` | GB |
| `a_i` | 允许卸载 | `Task.allow_offload=1` | 0/1 |
| `m_i^{off}` | 必须卸载 | `Task.must_offload=1` | 0/1 |
| `F_jq` | 边缘/云 CPU、NPU、FPGA 算力 | `edge_speed_matrix/cloud_speed`，最慢边缘资源为 120 | GFLOP/s |

| `B` | 无线上行带宽 | `radio_bandwidth_mhz` | MHz |

| `p^{cir}` | 无线电路功率 | `uplink_circuit_power_w` | W |

拓扑参数按 `default/high_congestion/small_smoke` 顺序取值。目标无向边数 `undirected_edge_links` 为 18/16/18，重构及热点刷新周期 `topology_period_slots` 为 5/4/2。非桥边通断概率 $p_{flap}$ 为 0.12/0.18/0.12，尖峰概率 $p_{spike}$ 为 0.15/0.25/0.15，带宽抖动半幅 $\sigma_R$ 为 0.25/0.35/0.25。各预设的 $\alpha_\rho=0.65$，时隙噪声为 $U[-0.15,0.15]$，有尖峰时额外叠加 $U[0.15,0.35]$。完整时序见数学模型第 0.4 节。

## 2. `observe()` 输出字典

- `nodes`: `[M+1,10]` float32，边缘+云节点特征（每种资源占用率、内存/存储、队列、邻域链路压力、度、云标志、总算力）。
- `adjacency`: `[M+1,M+1]` float32，含自环，GAT邻居注意力的掩码；**云端只保留自环**，防止所有边缘节点通过云端形成两跳“超级连接”。物理边云链路仍保留在环境的 `self.adj`。
- `edges` 为 `[M+1,M+1,4]` float32，默认形状 `[13,13,4]`。最后一维顺序为归一化当前带宽、有效拥塞率、归一化传播时延、背景拥塞趋势 $\Delta\rho_{mn}(t)$。有效拥塞率为背景拥塞率加本时隙已预留 MB 占可用容量 `(1-rho)*rate*slot_seconds/8` 的比例。
- `task`: `[8]` float32，输入、输出、计算、截止、优先级、内存、类型、卸载许可（恒为 1）。
- `source`: 任务接入边缘节点的整数下标。
- `candidate_features`: `[K,10]`，动态K项候选动作的属性。
- `candidate_targets`: `[K]`，候选目标图节点下标。
- `candidate_paths`: `[K,M+1]`，路由中经过节点的归一化掩码，用于路径节点嵌入均值。
- `global_features`: `[9]` float32，包含任务/完成/时隙进度、累计时延能耗、已结束与当前时隙负载；仅使用决策前可知信息。

GAT 图含 12 个边缘和 1 个云节点。24 个端侧任务源通过任务特征和接入边缘下标进入策略。

## 3. 动作与约束落地

- 候选动作记录估计时延/能耗、`destination`、`resource`、`path`、算力 `f`、固定传输项以及 Dinkelbach 得到的 `p_up`/上行速率；接收后分配记录再保存实际时延/能耗、逐链路扰动、算力退化和实际结束时刻。`step()` 的 `info` 额外暴露 Dinkelbach residual、可行候选数及任务/组修正/负载/约束 reward 分量。
- `destination=-2` 表示拒绝（`y_i=0`）；接收（`y_i=1`）时 `0..M-1` 表示边缘，`M` 表示云，对应唯一选中的执行节点 `x_ij=1`。
- `resource=0,1,2` 分别代表 CPU/NPU/FPGA，对应选中的异构资源 `g_ijq=1`。
- 接入边缘执行时 `path=(s(i),)`，其他边缘为简单路径 `(s(i), ..., d(i))`，上云为 `(s(i), M)`，拒绝为空。只有边缘间上传弧对应 `z_{i,mn}=1`。下行沿反向路径计时、计能耗并占用反向容量。
- `EdgeEnv._make_candidates()` 负责将可行性约束直接体现为候选动作集合。拒绝动作始终存在，是问题中 `y_i=0` 的合法决策。
- `EdgeEnv.step()` 修改时隙占用；算力、内存、存储和队列在实际完成后的首个时隙起点释放，链路占用按时隙释放。任务一旦接收，`y_i=1`，否则0；每个动作信息可以唯一重建 `x,g,z`。
- `mean_hops_accepted` 是平均跳数，仅统计已接收任务的边缘—边缘转发跳数；`mean_path_length` 是平均传输路径长度，按已接收任务的单向传输段数统计，接入边缘为1、远端边缘为1+边缘间转发跳数、云端为2。

## 4. v6 仿真简化与研究边界

| 项目 | v6 采用的模型 | 可扩展的研究内容 |
| --- | --- | --- |
| 功率优化 | Dinkelbach 求 `R(p)/(p+p_c)`，含最低速率约束 | 扩展多用户干扰与联合带宽分配 |
| 计算能力优化 | 在途份额冻结；本时隙新任务使用剩余容量做 KKT active-set 并发分配 | 扩展剩余工作量、抢占与迁移开销 |
| 无线接入 | 单接入节点，峰值速率抽样后反推信道增益，按 Shannon 公式计算 | 使用场景化信道增益、干扰与带宽调度 |
| 服务可用 | 显式 `service_deployment` 矩阵；云端部署全部服务 | 依据实际部署矩阵与模型文件状态 |
| 任务流 | 非平稳突发 Poisson 到达与周期热点；deadline 由源端实际无线传输与计算参考时间乘松弛系数生成 | 根据场景生成器或真实trace配置 |
| 路由 | 枚举4跳以内简单路径，按当前估计输入传输时间每个远端边缘最多保留 3 条 | 全部可行路径或经过论证的受控候选数 |
| 链路带宽 | 边缘间带宽每时隙相对基准抖动；每条有向弧分别预留输入和反向回传数据，合计不超过本时隙可用容量 | 排队、实际吞吐、跨时隙转发和流量调度 |
| 下行回传 | 使用上传路径的逆向路径，计入每跳时延、能耗和反向容量 | 独立优化下行路由与发射功率 |
| 中继能耗 | 转发平均功耗×逐跳通信时间 | 细分发射/接收/空闲功耗与链路资源管理 |
| 端侧角色 | 仅产生任务及无线上传/接收结果，计算、内存、存储和队列约束作用于边缘和云 | 基于实测设备刻画无线收发电路能耗 |
| 执行不确定性 | 每时隙先更新可观测拥塞；接收后依据当前拥塞确定逐弧扰动幅度，并抽取任务级算力退化 | 基于实测分布或相关随机过程建模 |
| 负载公平 | 每时隙末汇总边缘节点利用率方差，包含在途份额 | 固定调度周期及业务类别分层统计 |
| 训练可视化 | 保存训练五指标曲线和固定验证集均值±标准差曲线 | 多种子置信区间和论文图表排版 |
| PPO实现 | GAE + shuffled mini-batch PPO-Clip，支持完整状态续训 | 并行环境和张量化变长图批处理 |
| 验证方式 | 可加 reward 不变量测试、固定种子贪心评估、best/last checkpoint、四方法聚合入口 | 实际执行论文预算并完成统计显著性分析 |

## 5. 必须重视的量纲

- `d_i/o_i` 是 MB，通信速率是 Mbps：单跳传输秒数 `8*d_i/C_mn`。
- `c_i` 是 GFLOP，`F_jq/f_ijq` 是 GFLOP/s：执行时间 `c_i/f_ijq` 秒。
- `slot_seconds` 是秒：单条链路在当前时隙可预留的数据量 `C_mn*slot_seconds/8` MB。
- `P` 是 W、`t` 是秒：能量 `E=P*t` J。
- 数据规模和带宽单位未统一之前，不应用任务完成率比较算法。

## 6. 工程边界

`AGENTS.md` 的“不写防御性代码”指避免冗余异常处理、重复校验和兜底分支；**物理约束的过滤必不可少**。为学术可复现而做的单次可行性回归测试也应当保留。
