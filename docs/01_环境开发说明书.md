# 动态多跳云边端异构任务调度环境开发说明书

**项目名**：`schedule_test`
**目标算法**：GAT-PPO
**研究任务**：在云–边–端异构计算环境中，联合决定任务接收、最终执行节点、内部计算资源和边缘间的多跳传输路径，使任务完成率、时延、能耗与负载分布综合改善。
**规范状态**：本文给出阶段 1A 定稿的 v6 开发规格。已有原型提供 PPO、Dinkelbach 上行能效和 KKT 并发算力子问题。v6 的配置、动态链路和四维边特征在阶段 1B 落地，实验结论以之后的实际评估为准。

## 1. 研究背景和问题定义

端侧传感器、相机、车辆和移动终端产生图像识别、目标检测、视频分析、语音处理、信号计算五类任务。接收的任务先经源端无线链路上传，在接入边缘、经边缘间转发到达的其他边缘或经接入边缘单跳上联的云端执行。结果沿原路径反向返回终端。

系统默认包含 **N=24 个端侧任务源、M=12 个区域边缘节点、C=1 个云节点**。端侧仅产生任务和收发数据，边缘和云端提供 CPU/NPU/FPGA 算力，并按服务部署和资源兼容性筛选执行位置。

**与单纯选择执行节点相比，新的决策耦合点**：例如高算力目标边缘节点可能只能经过低带宽或拥塞的中继节点才能到达，故任务完成代价由目的节点资源与多跳路径共同决定。图注意力网络使用节点、边和邻域关系构造表示，PPO为可行候选动作评分。

## 2. 端到端系统结构

```text
端侧任务源（五类任务）
           │
           ▼
任务属性 + 当前接入边缘节点 + 源端实际无线速率
           │
           ├────────────── 当前动态边缘拓扑 G(t) ───────────────┐
           │                  带宽/拥塞/时延/趋势              │
           │                                                  ▼
           │                                         GAT(节点特征、边特征)
           │                                                  │
           └──────────────> 可行候选动作集 <────────────────────┤
                              │                           PPO Actor/Critic
                              ▼                                  │
              (执行节点j、资源q、路径P) <──────────────────────────┘
                              │
             无线接入/多跳转发 + CPU/NPU/FPGA 计算执行
                              │
             更新时隙链路容量、计算/内存/存储与队列占用
                              │
            计算成功、总时延、总能耗与负载方差 → 即时奖励
                              │
                    PPO-Clip更新策略 → 下一任务
```

## 3. 全部对象与状态

### 3.1 网络与拓扑

- 端侧任务源集合为 `U`，区域边缘集合为 `E`，计算节点集合及每项任务的候选执行范围均为 `V_i = V = E ∪ {c0}`。
- 边缘层为有向图 `G_e(t)=(E,L_ee(t))`；一条物理双向链路可生成两个方向的传输弧。
- 每条有效有向弧维护背景拥塞基线、当前拥塞及变化量、传播时延、转发功率和本时隙预留传输量。边缘间链路另存基准带宽，每时隙按相对抖动幅度从基准计算当前带宽。
- 可用速率：`C_mn(t) = (1-rho_mn(t))*R_mn^ee(t)`，单位 Mbps。
- 默认重构 12 节点环并加 6 条随机弦，目标 18 条无向边，平均度 3.0，图直径设计值约 3–4 跳。每 5 个时隙重构并刷新热点（20 个时隙的周期起点为 0、5、10、15）。期间非桥边以 0.12 的概率断开，以同一概率恢复或激活新边，保持连通且边数至多为目标值。
- 有向弧的背景拥塞服从均值回归的 AR(1) 过程，系数 0.65，均匀噪声范围 [−0.15, 0.15]。默认以 0.15 的概率叠加 [0.15, 0.35] 的均匀尖峰，再裁剪到背景拥塞区间。边缘间带宽每时隙抖动 ±25%。高拥塞配置的目标边数、周期、通断概率、尖峰概率和带宽幅度分别为 16、4、0.18、0.25 和 ±35%。完整公式见数学模型第 0.4 节。
- 源终端和边缘从 0 编号，接入边缘为 `s(i) = u_i mod M`，默认每个边缘绑定两个终端。
- 云与各边缘节点存在单跳广域网络连接；当前云端不作为边缘—边缘中继。GAT的邻接矩阵也不把云端当作边缘节点之间的消息传播捷径，云节点仅保留自身特征。

### 3.2 任务到达

每个任务 `tau_i` 包含 `(t_i^{arr}, u_i, k_i, d_i, c_i, o_i, priority_i, D_i, m_i, s_i, a_i, m_i^{off})`。

- 输入大小 `d_i`: 0.5—8 MB；输出大小 `o_i`: 0.05—1 MB。
- 计算量 `c_i`: 0.5—10 GFLOP；需求内存 `m_i`: 0.2—2 GB；需求存储 `s_i`: 0.1—2 GB。
- 优先级 `priority_i`: 1—5；截止时延 `D_i` 由输入上传、结果回传与计算参考时间之和乘以松弛系数生成，不再独立抽样。
- 每个端侧节点先在 `radio_rate_min_mbps=60` 到 `radio_rate_max_mbps=180` 之间抽取实际无线速率；任务使用其源终端实际速率计算输入与输出传输预算，并使用 `edge_speed_matrix` 中的最慢边缘资源算力 `120 GFLOP/s` 计算执行预算。松弛系数默认从 `deadline_slack_min=1.8` 到 `deadline_slack_max=3.0` 均匀抽样，为最多 4 跳的边缘传输预留工程时间，不做 deadline 上限截断。
- 所有任务均固定 `a_i=1, m_i^{off}=1`。每次决策可拒绝，或在具备服务、资源及可行传输路径的边缘或云端接收执行。
- 默认 episode 含 20 个时隙，每时隙到达数为 `max(1, Poisson(lambda_t))`，基础到达率在 `default/high_congestion/small_smoke` 中分别为 18.0/24.0/5.0 项每时隙。突发概率为 0.15，倍率为 2.5。`small_smoke` 含 4 个时隙，每 2 个时隙重构。
- 每个拓扑周期开始时重抽 `ceil(0.3*N)` 个热点终端。任务源以 0.6 的概率从热点中均匀抽取，其余从所有终端中均匀抽取。任务属性随机生成，但 deadline 与其输入量、输出量、计算量和源端速率联动；模拟器不使用真实业务 trace。

### 3.3 计算资源

边缘的 `edge_speed_matrix` 按 CPU/NPU/FPGA 排列。边缘 0、4、8 为 NPU 强型 [150,520,150]，1、5、9 为 FPGA 强型 [150,150,520]，2、6、10 为 CPU 强型 [420,180,180]，3、7、11 为轻量中继 [120,120,120]，单位均为 GFLOP/s。轻量中继也可执行其部署服务支持的任务。云端算力为 [8000,12000,8000]，部署全部五类服务。

边缘的 `service_deployment` 为 12×5 稀疏矩阵，逐行取值见数学模型 C6 的部署与算力表。每类服务各有 4 个边缘副本，均匀接入与类型分布下直接命中约 33.3%。约 2/3 的任务若接收，需转发至其他边缘或云端。执行还须满足资源兼容关系 `r_jqk`。模型保留按类型细化的额外开销 `omega_jqk`，原型取零。

**当前实现**：采用 CPU/NPU/FPGA 三类配置、兼容表和任务内存/存储/队列需求。同一到达时隙、同一节点、同一资源上的新任务由 KKT active-set 统一分配可用算力；此前时隙的在途任务份额冻结并先从总容量中扣除。新任务加入时只重分配本时隙同组任务，并同步修正其实际时延、能耗和奖励。

## 4. 仿真时间、任务调度流程

采用时隙 `t=0,1,...`，时隙长度 `Delta t=1 s`。一个时隙内多个任务按到达顺序依次生成动作、逐步占用同一个链路容量和计算/内存/存储/队列容量。时隙起点释放实际结束时刻不晚于当前起点的任务；其余任务成为在途任务，算力份额冻结并持续占用节点资源。链路占用按时隙清零。deadline 可以超过1秒。

1. 读取或产生任务 `tau_i`，定位接入边缘节点 `s(i)`。
2. 获取网络图及CPU/NPU/FPGA等资源状态；形成GAT输入。
3. 目标只枚举接入边缘、其他边缘和云。对每个远端边缘，从不超过 4 跳的简单路径中按当前估计输入传输时间保留至多 3 条。
4. 对每个候选目的节点和路径，使用可观测拥塞和标称算力检查服务、资源、容量及估计截止时延。不可行候选不生成；另设置一个任务拒绝动作。
5. GAT抽取节点及邻居特征，Actor为每个候选动作计算logit，经Categorical分布采样。
6. 若接收任务，每条实际经过的有向弧按当前背景拥塞取扰动半幅 `0.15*(0.5+rho_mn(t))`，在正负半幅间均匀抽样，计算速率按任务级 `eta_i ~ U[0,0.2]` 退化。固化这些扰动后计算实际时延、能耗与完成状态；拒绝时根据是否存在可行接收动作结算约束惩罚。
7. 保存 `(obs, action, old_logprob, reward, value)`；一轮任务结束后，使用GAE与PPO-Clip更新。
8. 输出调度方案及四目标统计；训练与评估使用隔离的随机种子。

### 路径示例

`u3 → e3(接入) → e1(中继) → e2(执行)`：`x_{i,e2}=1`，`z_{i,3,1}=1`，`z_{i,1,2}=1`。只有执行节点和异构计算资源负责计算任务，其余边缘节点只负责数据转发。

## 5. 建模和物理量

### 5.1 通信时延

任务输入数据量 `d_i` 以 MB 表示，链路速率以 Mbps 表示，注意乘 `8`：

`T_i^up = T_i^access + sum_{(m,n) in route_i} [8*d_i/C_mn(t) + T_mn^queue + T_mn^prop]`

`T_i^all = T_i^up + T_i^waiting + T_i^computing + T_i^down`。

当前实现中 `T_mn^queue` 用链路当前时隙占用率的简单函数近似，`T_i^computing = c_i/f_ijq`。输出数据沿上传路径的反向路径返回，按输出数据量占用反向链路容量，并计入逐跳排队、传播时延和中继能耗；终端无线下行时延为 `8*o_i/R_down`，其中 `R_down` 取源端峰值速率，相应接收电路能耗为 `p_cir*8*o_i/R_down`。独立优化下行路径不在当前决策空间内。

### 5.2 能耗

`E_i = E_i^radio_up + E_i^radio_down + E_i^forward_up + E_i^forward_down + P_jq^comp * T_i^computing`。

当前计算正向上传、反向输出回传和计算功耗，不计静态设备开机能耗。物理双向链路的两个方向分别计量容量；正式扩展仍需明确设备空载能耗和更细的收发功耗口径。

### 5.3 负载公平性

定义边缘节点 `lambda_j(t) = (sum_i sum_q f_ijq) / F_j`，边缘负载方差 `D_load(t) = (1/|E|) sum_j (lambda_j(t) - mean(lambda(t)))^2`，目标为最小化。

`mean_load_variance` 在每个时隙结束时只对边缘节点计算一次利用率方差，利用率同时包含在途和本时隙新任务，再对 episode 内时隙取平均。

## 6. 优化目标和约束

四个评价目标：`max R_suc`、`min T_avg`、`min E_avg`、`min D_load`。训练奖励与论文公式一致，完成、时延、能耗和负载系数比例为 `2:1:1:1`：

`r_i = 2*delta_i - y_i*(t_i + E_i) - D_load - Omega_i`。

其中 `delta_i` 由实际时延判定，`y_i` 是接收指示；时延、能耗和负载方差按1.0 s、3.0 J 和 `D_ref`（阶段 1B 后用种子 1042–1046 实测回填）归一化。`Omega_i` 分别惩罚接收但未按期完成、不可行动作和有可行动作时主动拒绝，三项默认均为1.0。

这里 `T_avg` 是成功任务的平均完成时延，`E_avg` 是成功任务的平均能耗，`R_suc = sum delta_i / N_T`。

`environment.py` 将当前任务实际任务项、同组旧任务因 KKT 重分配产生的任务项变化、当前时隙边缘负载方差增量及约束项计入单步 reward。各步负载增量在时隙内望远镜求和；未折扣 episode reward 满足 `episode_reward/N_T=objective_score`。

**C1—C24 完整编号、解释、公式见 `02_数学模型与C1-C24约束.md`。** C1—C18沿原有“支持变量→任务与资源→无线接入→功率/时延”顺序，C7/C8面向多跳作适配，C19—C24是路径、流量、无环与容量规则。

## 7. 软件架构和接口

### `topology.py`
- `make_topology(...)` 构建连通稀疏图并初始化链路属性。v6 时隙推进需维护有效边、拥塞基线和趋势、边缘间基准与当前带宽。
- `simple_routes(adj, source, dest, max_hops) -> list[tuple[int,...]]`：枚举简单路径，默认不经云端中继。

### `tasks.py`
- `Task`：任务参数结构。
- `sample_tasks(...)`：生成任务序列，deadline 按源终端实际无线速率、任务输入/输出量、计算量与配置化松弛系数联动生成。

### `environment.py`
- `EdgeEnv(cfg).reset() -> observation`：重置、生成任务图和资源状态。
- `EdgeEnv.observe() -> dict`：GAT输入和合法候选动作。
- `EdgeEnv.step(action_index) -> (obs, reward, done, info)`：一次调度，更新链路/计算资源。
- `EdgeEnv.metrics() -> dict`：成功率、时延、能耗、负载方差、平均跳数与回报。

### `models/gat.py` 和 `models/policy.py`
- 两层 GAT（`GraphAttentionLayer`）按归一化当前带宽、有效拥塞率、归一化传播时延、拥塞变化趋势 Δρ 的顺序读取边特征，输出每个边缘/云节点嵌入。
- PPO Actor 输入源节点嵌入、目标节点嵌入、路径池化嵌入、任务特征、候选属性和全局调度进度；输出候选动作分数。
- PPO Critic 输入源节点、全图汇聚表示、任务特征和全局历史统计；输出价值估计。
- `--model ppo` 关闭图消息传播，作为不使用GAT的消融基准（不涉及MPPO对比）。

### `algorithms/ppo.py`
- 对一整轮轨迹计算GAE优势估计。
- 按 PPO-Clip 优化策略损失，并对 Critic 使用平方误差；每轮记录策略/价值损失、熵、KL、裁剪比例、解释方差和梯度范数。
- 每个 PPO epoch 先随机打乱整条轨迹，再按 `ppo_batch_size` 分组更新；变长候选动作仍逐观测前向，batch 内损失取均值后执行一次优化器更新。默认每轮含20个时隙，任务步数随到达过程变化；更新5个 PPO epoch，mini-batch为64。
- 两层GAT的隐藏维度均为256，Actor/Critic头隐藏维度均为128。共享GAT与Actor头使用3e-4学习率，Critic头使用1e-3学习率；同一Adam通过两个不重叠参数组更新。
- 执行 `python src/train.py` 开始训练；每隔固定 episode 在5个固定验证种子上贪心评估，保存 `best_gatppo.pt` / `best_ppo.pt`、`last_gatppo.pt` / `last_ppo.pt`、`evaluation_metrics.jsonl` 和独立评估曲线。用 `Ctrl+C` 中断时，会根据已落盘的 JSONL 生成已有曲线并保存 last checkpoint；如尚未到首次固定评估，则只生成训练曲线。
- 训练入口通过 `--device auto|cpu|cuda` 选择模型设备，通过 `--threads` 设置 PyTorch CPU 线程数；实际设备与线程数写入训练配置快照。物理环境的动态路径和约束判断保留在 CPU，神经网络前向与 PPO 更新可放到 GPU。旧的32维GAT设备基准不再代表当前256维、5个PPO epoch配置，正式训练前应重新对比 CPU 与 GPU。

### `continuous.py`
- `choose_uplink_power(...)`：用 Dinkelbach 法最大化 `R(p)/(p+p_c)`，并满足截止时间导出的最低上行速率；默认最多迭代4次，收敛阈值为 `1e-3`。
- `allocate_compute(...)`：求解带每任务最低算力约束的优先级加权完成时间凸子问题，使用 KKT active-set/water-filling。
- **实现边界**：固定离散选择和并发组后，KKT 求解算力凸子问题；Dinkelbach 按容差或迭代上限返回上行功率。两者的最优性结论仅适用于各自的数学子问题。

## 9. 开发验收标准

1. 每次训练可生成一轮任务并至少执行一个完整轨迹，无运行中断。
2. 任意被采样的多跳动作所含链路全部存在，路径简单无环，路径终点等于选择的边缘执行节点，跳数≤4。
3. 同一时隙被占用的数据量不超过该链路的可用时隙容量；计算、内存和队列不超过限额。
4. 接收动作的目标只含边缘和云，拒绝始终合法。接入边缘执行或经其直接上云时，边缘间路由变量均为零。每个时隙的边缘子图保持连通，边数不超过配置目标，GAT 边特征最后一维反映背景拥塞的变化。
5. 同时记录 `R_suc,T_avg,E_avg,D_load`；训练奖励单独输出，不能用奖励曲线替代四目标对比。
6. 测试同网络与跨拓扑的GAT-PPO vs 无GAT消融，固定相同数据、种子与训练预算。

上述 v6 场景的验收在阶段 1B 实现后进行；算法相对提升、跨拓扑泛化和统计显著性以阶段 D–E 的实际实验为准。
