# 动态多跳云边端异构任务调度环境开发说明书

**项目名**：`schedule_test`
**目标算法**：GAT-PPO
**研究任务**：在云–边–端异构计算环境中，联合决定任务接收、最终执行节点、内部计算资源和边缘间的多跳传输路径，使任务完成率、时延、能耗与负载分布综合改善。
**规范状态**：开发规格说明 + 可运行研究原型；四目标及数学约束完整描述，已实现 Dinkelbach 上行能效与 KKT 并发算力连续子问题，完整论文实验仍待多种子和跨拓扑验证。

## 1. 研究背景和问题定义

考虑端侧传感器、相机、车辆、移动终端等产生图像识别、目标检测、视频分析、语音处理、信号计算五类智能任务。任务可以在产生任务的端侧设备本地执行，或经无线接入链路进入区域边缘服务器，或继续经多跳边缘链路转发到其他区域的边缘服务器执行；云端用于复杂任务的辅助执行及全局服务。

系统包含 **N=20 个端侧计算节点、M=6 个区域边缘节点、C=1 个云服务器**。边缘间建立8—10条无向双向链路组成稀疏连通图，拓扑与链路负载随时间变化。边缘节点内部存在 CPU/NPU/FPGA 等计算资源，不同任务和资源的兼容性不同。

**与单纯选择执行节点相比，新的决策耦合点**：例如高算力目标边缘节点可能只能经过低带宽或拥塞的中继节点才能到达，故任务完成代价由目的节点资源与多跳路径共同决定。图注意力网络使用节点、边和邻域关系构造表示，PPO为可行候选动作评分。

## 2. 端到端系统结构

```text
端侧任务队列（五类任务）
           │
           ▼
任务属性 + 当前接入边缘节点 + 端侧功率/资源状态
           │
           ├────────────── 当前动态边缘拓扑 G(t) ───────────────┐
           │                  链路容量/拥塞/时延               │
           │                                                  ▼
           │                                         GAT(节点特征、边特征)
           │                                                  │
           └──────────────> 可行候选动作集 <────────────────────┤
                              │                           PPO Actor/Critic
                              ▼                                  │
              (执行节点j、资源q、路径P) <──────────────────────────┘
                              │
             无线接入/多跳转发 + CPU/NPU/FPGA 计算执行
                              │
             更新时隙链路容量、计算/内存/存储与队列占用
                              │
            计算成功、总时延、总能耗与负载方差 → 即时奖励
                              │
                    PPO-Clip更新策略 → 下一任务
```

## 3. 全部对象与状态

### 3.1 网络与拓扑

- 云节点集合 `C={c0}`；区域边缘集合 `E={e0,...,e(M-1)}`；端侧集合 `U={u0,...,u(N-1)}`。
- 边缘层为有向图 `G_e(t)=(E,L_ee(t))`；一条物理双向链路可生成两个方向的传输弧。
- 每条弧 `(m,n)` 记录：是否连通 `a_mn(t)`、标称速率 `R_mn^ee(t)`、背景占用率 `rho_mn(t)`、可用速率 `C_mn(t)`、传播延时 `t_mn^prop`、转发功率 `P_mn^fwd`，以及当前时隙的已占用传输量。
- 可用速率：`C_mn(t) = (1-rho_mn(t))*R_mn^ee(t)`，单位 Mbps。
- 初始构图：一个6节点环保证连通，再加入2—4条非环边，总计8—10条无向边。当前骨架采用固定9条；每 `topology_period_slots` 重新采样拓扑，其余时隙变化背景拥塞。
- 每个端侧节点 `u_i` 绑定一个可用无线接入边缘节点 `s(i)`。该绑定可以扩展为多基站覆盖，但**当前版本只使用一个接入边缘节点**。
- 云与各边缘节点存在单跳广域网络连接；当前云端不作为边缘—边缘中继。GAT的邻接矩阵也不把云端当作边缘节点之间的消息传播捷径，云节点仅保留自身特征。

### 3.2 任务到达

每个任务 `tau_i` 包含 `(u_i, k_i, d_i, c_i, o_i, priority_i, D_i, m_i, s_i, a_i)`。

- 输入大小 `d_i`: 0.5—8 MB；输出大小 `o_i`: 0.05—1 MB。
- 计算量 `c_i`: 0.5—10 GFLOP；需求内存 `m_i`: 0.2—2 GB；需求存储 `s_i`: 0.1—2 GB。
- 优先级 `priority_i`: 1—5；截止时延 `D_i`: 50—500 ms。
- `a_i=1` 表示允许离开任务源端侧节点卸载。
- 200—1000任务/次实验；同一时隙到达多任务。骨架默认一轮600项，12项共享1秒时隙。
- 当前使用随机独立生成任务，模拟器不使用真实业务trace；后续可以替换为CSV任务到达文件。

### 3.3 计算资源

区域边缘服务器内设 CPU/NPU/FPGA 三种计算资源；云端也抽象为3种资源。不同资源对五类任务具有不同支持关系 `r_jqk`。数学模型保留可按任务类型细化的额外开销 `omega_jqk`，当前代码取 `omega_jqk=0`。每个节点记录计算能力、内存/存储、队列、服务可用性、资源占用和剩余容量。

**当前实现**：采用 CPU/NPU/FPGA 三类配置、兼容表和任务内存/存储/队列需求。同一时隙、同一节点、同一资源上的并发任务由 KKT active-set 统一分配算力，并满足截止时间导出的最低算力约束；新任务加入时会重分配该组已有任务并同步修正时延、能耗和统计值。

## 4. 仿真时间、任务调度流程

采用时隙 `t=0,1,...`，时隙长度 `Delta t=1 s`。一个时隙内多个任务按到达顺序依次生成动作、逐步占用**同一个**链路容量/计算份额/队列容量；本时隙结束后释放资源预留，下时隙重新生成链路背景拥塞。时隙级容量与单个任务时延是两个不同的量。

1. 读取或产生任务 `tau_i`，定位接入边缘节点 `s(i)`。
2. 获取网络图及CPU/NPU/FPGA等资源状态；形成GAT输入。
3. 枚举**可行、无环、长度不超过4跳**的边缘间简单路径。目标节点可以是接入边缘、其他边缘、云端或任务源端侧节点。
4. 对每个候选目的节点和路径检查服务可用、异构资源支持、内存、存储、队列、计算容量、链路余量及截止时延。不可行候选不生成；另设置一个任务拒绝动作。
5. GAT抽取节点及邻居特征，Actor为每个候选动作计算logit，经Categorical分布采样。
6. 若接收任务，则占用目标资源和路径带宽并累加端到端时延、通信/中继/计算能耗；否则仅更新拒绝统计。
7. 保存 `(obs, action, old_logprob, reward, value)`；一轮任务结束后，使用GAE与PPO-Clip更新。
8. 输出调度方案及四目标统计；训练与评估使用隔离的随机种子。

### 路径示例

`u3 → e3(接入) → e1(中继) → e2(执行)`：`x_{i,e2}=1`，`z_{i,3,1}=1`，`z_{i,1,2}=1`。只有执行节点和异构计算资源负责计算任务，其余边缘节点只负责数据转发。

## 5. 建模和物理量

### 5.1 通信时延

任务输入数据量 `d_i` 以 MB 表示，链路速率以 Mbps 表示，注意乘 `8`：

`T_i^up = T_i^access + sum_{(m,n) in route_i} [8*d_i/C_mn(t) + T_mn^queue + T_mn^prop]`

`T_i^all = T_i^up + T_i^waiting + T_i^computing + T_i^down`。

当前实现中 `T_mn^queue` 用链路当前时隙占用率的简单函数近似，`T_i^computing = c_i/f_ijq`。输出数据沿上传路径的反向路径返回，按输出数据量占用反向链路容量，并计入逐跳排队、传播时延和中继能耗；终端无线下行采用峰值速率模型。独立优化下行路径不在当前决策空间内。

### 5.2 能耗

`E_i = E_i^radio_up + E_i^radio_down + sum_{(m,n) in route_i} P_mn^fwd * T_i,mn + P_jq^comp * T_i^computing`。

当前计算正向上传、反向输出回传和计算功耗，不计静态设备开机能耗。物理双向链路的两个方向分别计量容量；正式扩展仍需明确设备空载能耗和更细的收发功耗口径。

### 5.3 负载公平性

定义节点 `lambda_j = (sum_i sum_q f_ijq) / F_j`，全局负载方差 `D_load = (1/|V|) sum_j (lambda_j - mean(lambda))^2`，目标为最小化。

`mean_load_variance` 在每个时隙结束时对端、边、云全部计算节点计算一次利用率方差，再对 episode 内时隙取平均；不对同一时隙的每个任务前缀重复采样。

## 6. 优化目标和约束

四个评价目标：`max R_suc`、`min T_avg`、`min E_avg`、`min D_load`。训练权重比例为 `2:2:1:1`：

`reward = 2*R_suc - 2*T_avg - E_avg - D_load`。

这里 `T_avg` 是成功任务的平均完成时延，`E_avg` 是成功任务的平均能耗，`R_suc = sum delta_i / N_T`。

由于 PPO 每个调度步都需要即时奖励，`environment.py` 使用截至当前任务的完成率、平均完成时延、平均任务能耗和平均负载方差直接计算 reward。

**C1—C24 完整编号、解释、公式见 `02_数学模型与C1-C24约束.md`。** C1—C18沿原有“支持变量→任务与资源→无线接入→功率/时延”顺序，C7/C8面向多跳作适配，C19—C24是路径、流量、无环与容量规则。

## 7. 软件架构和接口

### `topology.py`
- `make_topology(rng, n_edges, link_count, ...) -> adj, rates, loads, prop`：构建连通稀疏图、初始拥塞、传播延时。
- `simple_routes(adj, source, dest, max_hops) -> list[tuple[int,...]]`：枚举简单路径，默认不经云端中继。

### `tasks.py`
- `Task`：任务参数结构。
- `sample_tasks(rng, n, terminals, edges)`：生成任务序列；后续引入场景模板。

### `environment.py`
- `EdgeEnv(cfg).reset() -> observation`：重置、生成任务图和资源状态。
- `EdgeEnv.observe() -> dict`：GAT输入和合法候选动作。
- `EdgeEnv.step(action_index) -> (obs, reward, done, info)`：一次调度，更新链路/计算资源。
- `EdgeEnv.metrics() -> dict`：成功率、时延、能耗、负载方差、平均跳数与回报。

### `models/gat.py` 和 `models/policy.py`
- 两层含边属性的 GAT (`GraphAttentionLayer`)，输出每个边缘/云节点嵌入。
- PPO Actor 输入源节点嵌入、目标节点嵌入、路径池化嵌入、任务特征和候选属性；输出候选动作分数。
- PPO Critic 输入源节点与全图汇聚表示和任务特征；输出价值估计。
- `--model flat` 关闭图消息传播，作为不使用GAT的消融基准（不涉及MPPO对比）。

### `algorithms/ppo.py`
- 对一整轮轨迹计算GAE优势估计。
- 按 PPO-Clip 优化策略损失，并对Critic使用平方误差。
- 每个 PPO epoch 先随机打乱整条轨迹，再按 `ppo_batch_size` 分组更新；变长候选动作仍逐观测前向，batch 内损失取均值后执行一次优化器更新。
- 执行 `python src/train.py` 即可开始默认训练；完整训练代码就在该文件中。终端先打印当前 `episode`，再打印累计奖励、任务完成率、任务平均完成时间、任务平均能耗和负载均衡度。训练结束后在同一结果目录生成五项曲线图 `training_metrics.png`；每个子图包含浅色真实值曲线和深色滑动窗口曲线，不使用圆点和图例。

### `continuous.py`
- `choose_uplink_power(...)`：用 Dinkelbach 法最大化 `R(p)/(p+p_c)`，并满足截止时间导出的最低上行速率。
- `allocate_compute(...)`：求解带每任务最低算力约束的优先级加权完成时间凸子问题，使用 KKT active-set/water-filling。
- **实现边界**：上述算法分别保证无线能效子问题和固定并发组算力子问题最优，不声称求得四目标混合整数原问题的全局最优解。

### 8.1 结果目录规范

每次运行 smoke、训练、评估或组合实验前，按北京时间创建独立目录 `results/YYYYMMDD_HHMMSS/`。同一次运行的模型权重、训练日志、评估指标、图表和配置快照必须放入该目录；不得把新产物直接写到 `results/` 根目录，不得覆盖已有测试目录。使用历史 checkpoint 做评估时，应在本次日志中记录 checkpoint 来源路径。

## 9. 开发验收标准

1. 每次训练可生成一轮任务并至少执行一个完整轨迹，无运行中断。
2. 任意被采样的多跳动作所含链路全部存在，路径简单无环，路径终点等于选择的边缘执行节点，跳数≤4。
3. 同一时隙被占用的数据量不超过该链路的可用时隙容量；计算、内存和队列不超过限额。
4. 端侧本地任务不使用边缘间路径；同一接入边缘执行也不占用边缘间链路。
5. 同时记录 `R_suc,T_avg,E_avg,D_load`；训练奖励单独输出，不能用奖励曲线替代四目标对比。
6. 测试同网络与跨拓扑的GAT-PPO vs 无GAT消融，固定相同数据、种子与训练预算。

当前源码已满足基本执行通路和核心约束回归测试；算法相对提升、跨拓扑泛化和统计显著性仍必须以阶段D—E的真实运行结果为准。
