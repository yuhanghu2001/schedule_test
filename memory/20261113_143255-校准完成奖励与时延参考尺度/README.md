# 校准完成奖励与时延参考尺度

## 对话目标

修复 deadline 放宽后时延尺度与 reward 归一化不匹配、接收长时延任务净回报过低所导致的完成率不收敛问题，并通过固定种子启发式对比和 100 轮从零训练验证。

## 已完成事项

- 将 `reward_accept` 从 `4.0` 调整为 `8.0`。
- 将 `reward_delay_ref` 从 `0.5` 调整为 `1.0`，匹配当前 deadline 放宽后的时延分布。
- 将 `reward_version` 更新为 `v3_accept8_delay1`，避免将新旧奖励标尺的 checkpoint 指标直接比较。
- 同步修改默认、高拥塞与 smoke 三套配置，以及 AGENTS、README、环境说明、数学模型和训练奖励说明。
- 新增固定种子回归测试，比较“接受所有可行任务”与“拒绝时延超过 0.9s 的任务”。

## 奖励公式

```text
J = 8*A/N
  - 2*T_sum/(N*1.0)
  - E_sum/(N*3.0)
  - sum(V_s)/(S*0.05)

r_t = 8*accepted
    - 2*delta_delay/1.0
    - delta_energy/3.0
    - (N/S)*delta_variance/0.05
```

## 验证证据

- 26 项单元测试全部通过，未折扣 reward 与 episode objective 不变量仍成立。
- 默认配置、固定种子 1042 的启发式对比：
  - 接受所有可行任务：`objective_score=4.807181`，完成率 `99.1667%`，条件拒绝率 `0%`。
  - 拒绝 `delay>0.9s` 的任务：`objective_score=4.085669`，完成率 `80%`，条件拒绝率 `19.3277%`。
- 使用 CPU 4 线程从零训练 100 轮，每 25 轮在种子 1042–1046 上固定评估：
  - 第 25 轮：完成率 `99.0667%`，条件拒绝率 `0%`。
  - 第 50 轮：完成率 `99.0333%`，条件拒绝率 `0%`。
  - 第 75 轮：完成率 `99.0333%`，条件拒绝率 `0%`。
  - 第 100 轮：完成率 `99.0333%`，条件拒绝率 `0%`，`objective_score_mean=5.618838`。
- 100 轮训练是开发验证，所有产物位于系统临时目录，读取证据后已删除，未写入 `results/`。

## 未解决事项和实现边界

- 100 轮、单一训练种子只能验证主动拒绝问题已在当前默认场景中消失，不构成多种子泛化或最优权重结论。
- 完成率提高不代表其他三项目标必然同步改善，正式实验仍需分别报告时延、平均能耗和负载不均衡度。

## 后续建议

- 正式训练应从零开始，不从 `v2_additive` 的旧 checkpoint 续训；完成多种子同预算实验后再评估 `8:2:1:1` 的稳定性。
