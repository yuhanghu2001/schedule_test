# 对齐 MPPO 表格训练与网络参数

## 对话目标

将当前 GAT-PPO 的每轮步数、Actor/Critic 学习率、PPO 更新轮数、GAT 与策略/价值头隐藏维度、Dinkelbach 参数与用户提供的表格对齐，并说明标准 PPO-Clip 不使用旧策略软更新系数的原因。

## 已完成事项

- 默认和高拥塞场景每轮任务步数调整为200；smoke 配置仍保留36个任务，避免将开发快速检查扩大为正式轨迹。
- 两层边特征GAT隐藏维度均从32调整为256，Actor/Critic头的隐藏维度均从64调整为128。
- PPO 每轨迹更新轮数调整为5，mini-batch保持64、`gamma=0.99`、`gae_lambda=0.95`和 `clip=0.2` 不变。
- 将单一 `learning_rate` 拆分为 `actor_learning_rate=1e-4` 和 `critic_learning_rate=1e-3`。同一Adam使用两个不重叠参数组：共享GAT、flat encoder和Actor头归Actor组，Critic头单独归Critic组。
- Dinkelbach 最大迭代次数从50调整为4，收敛阈值从 `1e-8` 调整为 `1e-3`。
- 训练和评估入口都按配置创建对应维度的模型，checkpoint配置快照包含网络尺寸和两组学习率。
- 同步更新 README、环境说明、实验设计和 PPO 对齐说明。

## 旧策略软更新说明

当前实现是标准 PPO-Clip：采样时保存旧策略的 `log_prob`，在同一轨迹的5个 PPO epoch 内将它固定为概率比分母，下一轨迹再直接用更新后的策略采样。因此没有独立的目标/旧策略网络需要用 `kappa=0.995` 做 Polyak 软更新。如果加入该系数，就是改成图中 MPPO 的旧策略网络变体，算法口径会发生变化。

## 验证证据

- 配置实际加载值：默认/高拥塞轨迹200步，PPO更新5轮，Dinkelbach为4次/`1e-3`。
- 模型实际结构：GAT `256->256`，Actor/Critic头隐藏维度均为128。
- Adam实际参数组：Actor组 `1e-4`，Critic组 `1e-3`。
- 27项单元测试全部通过，新增回归测试固化表格参数、网络尺寸和优化器学习率。
- 系统临时目录的1轮完整训练成功，生成训练/评估 JSONL、两张图、best/last checkpoint；临时产物已删除，未写入 `results/`。

## 未解决事项和后续建议

- GAT 是 Actor 与 Critic 共享表示，本实现将其归入Actor学习率组；Critic损失仍会通过共享GAT反向传播，但GAT参数以1e-4步长更新。
- 256维GAT与5个PPO epoch改变了计算量，旧的32维模型 CPU/GPU 基准已失效，正式长训练前应重新测量设备性能。
- Dinkelbach 迭代预算收紧到4次、阈值放宽到 `1e-3` 后，应在正式实验中同时检查速度与残差精度。
