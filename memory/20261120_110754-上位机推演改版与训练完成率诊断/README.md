# 上位机推演改版与训练完成率诊断

## 对话目标

完善云边端调度上位机的展示与操作，解释新旧实验中任务完成率的变化，并按用户要求提交当前工作区到 GitHub。此前的启动、拓扑重绘和训练入口整合见[历史记录索引](../README.md)。

## 已完成事项

- 根目录使用 `npm start` 启动前端、FastAPI 和 MySQL。前端端口为 8888，FastAPI 端口为 8000。主导航为「系统总览」「拓扑监控」「节点管理」。
- 总览左上只展示任务完成率、任务平均完成时间、任务平均能耗、负载均衡度。左下为调度策略，右下为资源利用率。右上「任务产生」在加载前显示真实环境预览，包括任务总数、已调度和待调度数量、五类业务分布、首个待调度任务详情。加载后随推演快照更新。
- 总览操作顺序为选择算法、任务加载、开始推演。运行中可暂停；已发出的请求返回后停在当前进度，继续时从同一会话推进。更换算法后需重新加载。策略面板说明共同流程并高亮所选算法。
  - 最短最快启发式依次优先选择更少跳数、更大分配算力、更低估算时延和更低估算能耗。
  - 贪心估计启发式在可行候选中最小化归一化时延和能耗的加权和。
  - 随机算法在可行候选和拒绝动作中等概率抽样。两种启发式在没有可行候选时才会拒绝任务。
- 总览和拓扑监控共用三层拓扑场景。边缘和云节点展示 CPU、NPU、FPGA 算力，金色标出最高项。三项算力相同时同色。E3、E7、E11 保留各 120 GFLOP/s 的算力，详情显示「算力均衡」。节点转发由具体路径决定。计算节点链路按拥塞改变颜色和线宽，悬停显示速率、拥塞及传输 1 MB 的双向单跳估算时延。独立拓扑页按最后一轮截图要求移除了底部波动面板、播放控制和曲线，使用环境预览快照。总览推演中继续使用实时会话快照更新拓扑并高亮路径。
- 节点管理去掉标题旁标签、底部说明、统计和分页，用固定表头和表内纵向滚动条浏览全部节点。类型筛选和搜索会回到表格顶部。

## 完成率诊断

诊断对象为 [results/20261119_220735](../../results/20261119_220735)，两种模型各训练 600 回合，使用五个固定验证种子。下表以全部到达任务为分母。

| 任务最终结果 | GAT-PPO | PPO |
| --- | ---: | ---: |
| 按期完成 | 41.92% | 41.62% |
| 有可行方案但主动拒绝 | 44.00% | 44.19% |
| 无可行方案而被迫拒绝 | 4.89% | 4.89% |
| 接收后超时 | 9.18% | 9.30% |

复现 GAT-PPO 第 600 回合结果后，发现 1,010 个主动拒绝任务中有 909 个需要至少一跳边缘或云端传输。主动拒绝任务的平均输入量为 5.37 MB，接收任务为 3.28 MB。使用同一权重、相同验证种子分别进行两项诊断重放：

- 仅把边缘链路带宽由 120–360 Mbps 提升到 500–2000 Mbps，按期完成率由 41.92% 升至 64.80%，综合得分由 −0.472 升至 0.032。
- 保留低带宽，只在策略主动拒绝时改选估算代价更低的可行方案，按期完成率升至 66.84%，综合得分降至 −1.093。增加接单的同时，完成任务的平均时延和能耗都有上升。

主动拒绝是本轮完成率下降的主要直接原因。带宽和奖励取舍都会影响结果。两项重放各自以原策略为对照，增幅不可相加。后续评估应在相同场景和种子下同时报告任务完成率、主动/被迫拒绝率、超时率、时延、能耗与负载均衡度。
