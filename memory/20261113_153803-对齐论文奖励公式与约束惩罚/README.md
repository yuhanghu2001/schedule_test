# 对齐论文奖励公式与约束惩罚

## 对话目标

将环境单步奖励严格改为论文图中的 `beta_1*delta-y*(beta_2*t+beta_3*E)-beta_4*D_load-Omega` 结构，四项系数比例固定为 `2:1:1:1`，并明确实现三种约束惩罚。

## 已完成事项

- 先更新 `docs/02_数学模型与C1-C24约束.md` 中的奖励假设和公式，再修改配置与环境代码。
- 将旧的增量奖励参数替换为 `reward_beta_completion=2.0`、`reward_beta_delay=1.0`、`reward_beta_energy=1.0`、`reward_beta_load=1.0`。
- 当前任务时延、能耗和动作后负载方差分别用 `1.0s`、`3.0J`和 `0.05` 归一化后代入公式。
- 增加 `omega_1`、`omega_2`、`omega_3` 三个独立参数，由于图中没有给出数值，工程默认均设为 `1.0`。
- `omega_1`：接收但未按 deadline 完成时惩罚。当前候选生成会预先排除这类动作，因此正常运行基本不可达，但分支已明确实现。
- `omega_2`：越界/不可行动作ID触发惩罚；PPO 的候选动作分布不会采样到该分支。
- `omega_3`：存在可行动作时主动拒绝触发惩罚；无可行动作时拒绝不惩罚。
- `objective_score` 改为 `episode_reward/N`，与新的带约束惩罚单步奖励口径一致。
- 奖励版本更新为 `v4_paper_formula_2_1_1_1`，旧 checkpoint 不用于新奖励口径续训。
- 同步更新三套配置、AGENTS、README、环境说明和 PPO 奖励说明。

## 当前单步公式

```text
r_i = 2*completed
    - accepted*(delay/1.0 + energy/3.0)
    - load_variance/0.05
    - constraint_penalty
```

## 验证证据

- 29项单元测试全部通过。
- 测试分别固化 `omega_2`、`omega_3`和无可行动作零惩罚口径，并验证时延、能耗、即时负载方差分量。
- smoke 完整运行36个任务，`episode_reward/N` 与 `objective_score` 均为 `-0.2326370590`，临时产物已自动删除。
- 单动作分量实测为 `2.0-0.384936-0.288254-0.025077-0=1.301732`，与环境返回 reward 完全一致。

## 未解决事项和后续建议

- `omega_1..omega_3=1.0` 是因图中未给数值而采用的明示工程默认值，正式论文如有另一张惩罚参数表，应用表中数值替换。
- 新奖励直接惩罚每个任务动作后的当前负载方差，不再使用增量望远镜形式，因此奖励数值与历史训练不可直接比较。
- 新奖励的正式训练必须从零开始，并分别报告完成率、平均时延、平均能耗和负载不均衡度。
